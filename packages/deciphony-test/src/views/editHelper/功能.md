## 高频几何预览：`updateVDom` + `scoreWriteGate.patch`

拖连音线这类「指针每帧都改 Frame / 附属符号 `data`」的操作，不要每帧直接写 `musicScore`：deep watch 会整谱跑 `musicScoreToVDom`，大谱会卡死。

约定（实现见 `scoreWriteGate.ts`，连音线示例见 `renderEditSlurDrag.ts` 的 `previewSlurDrag`，垂直符号见 `renderEditArpeggioDrag.ts` / `renderEditStrummingDrag.ts`，横向符号见 `renderEditPedalDrag.ts` / `renderEditPitchDrag.ts` / `renderEditLineDrag.ts` / `HorizontalDragHandles.vue`）：

1. **立刻改视图**：`musicScoreRef.updateVDom(targetId, patch)` —— 按 id 找到现有节点，**原地 assign**（不换数组、不换节点引用）。连音线用 renderer 的 `slurVDomPatch` 生成 patch。
2. **改源数据**：一律经 `scoreWriteGateFor(musicScore, getUpdateVDom).patch({ key, mirror?: { targetId, patch }, commit, delay? })`。默认 `delay = 100ms`，同一 `key` 只保留最后一次 `commit`；停手后再写入，整谱布局只跑一次。
3. **结构变更**（增删音符/小节等）用 `delay: 0`，立刻 `commit`。
4. **把手叠层**：拖拽中把手坐标用独立 override（如 `slurHandleOverride`），不要为了跟手去改编辑器的 `vDomList`。`vDomList` 必须用 `shallowRef`（不要 `ref`，否则上万节点会做成深层响应）。查找走 `renderMusicScore` 的 `info.lookup`。宿主注入扩展用固定数组引用（如 `const scoreExtensions = [editExtension]`）。
5. 卸载前 `flushScoreWrites(musicScore)`，避免未落盘的 commit 丢失。
